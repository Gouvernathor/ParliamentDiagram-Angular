# ParliamentDiagram

This is meant to be(come) a v2 of the parliamentdiagram website.
The sought improvements are:

- no more python to generate the arches, forcing it to the backend : use the typescript @parliamentdiagam packages to do it in-browser, and have a static website (except oauth)
- no more python at all : if a backend is necessary (for the oauth), it will be for NodeJS
    - that will be a hard part, but mandatory before hoping to replace the main website on the original URL
- cleaner and more maintainable code using Angular, no more content generated by DOM API : HTML, CSS and JS code each in their file types
- improve the layout maybe (using Material because of better Angular integration), though the base one isn't bad
- add a majority calculator, to simulate how each party votes and predict whether something will pass or not
    - though it will require presets pre-filled with party numbers to be really usable, so maybe it won't fit with the rest of the website

This project was generated using [Angular CLI](https://github.com/angular/angular-cli) version 21.2.11.

## Deployment

This is a static web[site/app] able to be deployed on about any domain.

A part of the features depend on being able to establish an OAuth 2 connexion to Wikimedia Commons, and that requires a set of oauth credentials tied to a particular callback URL. Four sets of credentials are provided:
- for localhost testing
- for the [Gouvernathor](parliamentdiagram.gouvernathor.fr) domain name
- for the [main Toolforge](https://parliamentdiagram.toolforge.org/) domain
- for the [beta Toolforge](https://parliamentdiagram-beta.toolforge.org/) domain

Building the app without specifying any configuration will build it with the OAuth-dependent features disabled.

A CI workflow exists to deploy to the Gouvernathor website, using either Gitlab CI for Gitlab Pages, or Forgejo Actions for Codeberg Pages. It is triggered by pushes on this repo and so is up-to-date with the latest state of the main branch.

Deployment on Toolforge is a bit more complex and triggered from the tool server, not from the pushes on this repo. It is handled using the [Toolforge deployer](https://codeberg.org/Gouvernathor/ParliamentDiagram-Toolforge-deployer) side repo.

## Development server

To start a local development server, run:

```bash
ng serve
```

By default, it will use the "development" configuration which uses the localhost oauth credentials.

The "development-no-oauth" configurations will have oauth disabled.

## Building

To build the project run:

```bash
ng build
```

This will compile your project and store the build artifacts in the `dist/` directory. By default, the production build optimizes your application for performance and speed.
